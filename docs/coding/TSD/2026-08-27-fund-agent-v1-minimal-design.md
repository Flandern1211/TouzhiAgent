# 基金分析 Agent v1 最小实现设计

- 状态：待实现
- 对应需求：[v1 需求规格](../../requirements/fund-agent-v1-requirements.md)

## 1. 设计目标

以最小可用闭环实现三类能力：多基金筛选、当前持仓快照分析、持续跟踪和系统内风险提醒。设计不引入交易执行、账户导入、外部推送或逐笔交易流水。

## 2. 运行边界

- 服务在用户本机运行，通过浏览器访问。
- 持久化使用服务器上的 MySQL 等基础服务；连接信息由配置提供。
- 默认数据获取使用公开来源的简单爬虫；每个来源可替换为通用 HTTP 爬虫 API。
- 业务结果必须保留来源、抓取时间、有效时间（如有）和原文链接。

## 3. 最小数据流

```text
手动基金/持仓输入
        ↓
基金身份解析（产品 + 份额类别）
        ↓
数据源适配（净值/公告/新闻/舆情）
        ↓
确定性指标与规则
        ├── 多基金客观/个性化排序
        ├── 组合收益/仓位/集中度/风险
        └── 异常触发
                    ↓
              Agent 证据复核
                    ↓
              系统内提醒与历史记录
```

## 4. 核心边界

### 4.1 基金与份额

产品身份和份额身份分开保存。输入代码优先作为主键线索，名称仅用于展示和辅助匹配。无法确认产品或份额关系时，系统应标记待确认，不把不同份额合并计算。

### 4.2 数据来源

来源适配器返回统一的带状态记录：来源类型、标的、抓取时间、数据时间、内容、原文链接、可信度和错误状态。默认爬虫与外部 API 使用同一返回合同。

来源优先级为官方事实、公开行情/净值、财经/行业新闻、社交媒体线索。冲突记录并展示，不静默覆盖。

### 4.3 评分与筛选

确定性计算产生可解释的分项指标和缺失状态，再按配置计算客观分数。个性化分数在客观分数基础上应用风险偏好和持有期限配置。LLM/Agent 只能解释和综合，不直接生成关键数值。

### 4.4 组合快照

快照保存代码/份额、金额或份额、累计投入、估值来源和快照时间。组合计算使用同一估值时点；无法统一时点时显示数据状态并降低结论可信度。

### 4.5 跟踪与风险

调度器按默认频率更新候选集合和当前持仓。规则检测净值异常、回撤、波动、规模/经理/持仓变化及高可信公告；规则命中后提交证据包给 Agent。Agent 输出风险等级、解释、不确定性和待核查事项。

同一基金和同类原因 24 小时内去重，风险升级立即新建提醒，恢复事件关闭当前提醒但保留历史。

## 5. 失败和安全处理

- 单一来源失败不阻塞其他来源，但必须记录失败状态。
- 数据过期、估算、缺失和冲突显式展示；证据不足时禁止高等级结论。
- API 密钥、数据库凭据只从运行时配置读取，不写入代码、报告或前端。
- 爬虫遵守目标站点访问条款、限频和 robots 要求。

## 6. 验证重点

- 基金代码、名称、份额类别识别错误和重复输入；
- 指标计算的边界值、缺失数据和估算值标记；
- 客观/个性化排序随配置变化；
- 当前持仓快照的收益、仓位、集中度和组合风险；
- 来源失败、冲突、过期数据和 Agent 证据不足；
- 提醒去重、升级、恢复和历史保留。
