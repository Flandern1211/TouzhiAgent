# 基金分析 Agent v1 需求规格

- 状态：已确认，v1 最小实现基线
- 版本：0.2
- 日期：2026-08-26

> 本文档只记录产品需求和边界，不规定技术路线、代码结构或具体实现方式。未列为“已确认”的内容，不应直接作为开发承诺。

## 1. 产品目标

为个人用户提供面向中国公募基金的研究辅助和风险监测能力。用户可以手动维护一组基金和自己的当前持仓，系统结合多来源信息进行比较、排序、组合风险分析和持续跟踪，并在风险明显升高时在系统内提示。

系统的输出用于研究和决策辅助，不自动连接券商、不自动下单。基金产品和份额类别必须分别识别，例如：

- 天弘机器人ETF发起式联接 C
- 南方致远混合 E

同一基金产品的 A、C、E 等份额不能被当作完全相同的标的处理；至少要保留产品关系和份额差异。

## 2. v1 已确认范围

### 2.1 三个核心使用场景

1. **多基金筛选**：用户手动输入多只基金，在输入集合内比较，筛选值得关注的基金。
2. **组合分析**：用户手动录入当前持仓快照，分析实际组合的收益、配置和风险。
3. **持续跟踪**：持续获取相关基金及其外部信息，发现风险增大时在系统内提醒。

### 2.2 基金范围

面向中国公募基金，v1 最小实现覆盖股票型、混合型、指数型和 ETF 联接基金，并识别 A/C/E 等份额类别。债券型、货币型、QDII、FOF 等类型允许被录入，但当数据或指标不适用时必须标记“暂不支持/数据不足”，不阻塞其他基金分析。

### 2.3 数据来源范围

跟踪需要综合以下来源：

- 基金净值、估值和其他公开行情数据；
- 基金公司、监管机构及其他官方公告；
- 财经新闻和行业新闻；
- 社交媒体及网络舆情。

默认使用简单公开爬虫，同时允许通过配置切换或接入外部爬虫 API。数据来源不能写死在业务逻辑中。

官方来源的可信度高于新闻，新闻高于社交媒体。社交媒体主要用于发现线索，不能在未经复核的情况下单独支撑高等级风险结论。

### 2.4 运行和存储边界

- 第一版全部使用 Python 实现。
- 服务运行在用户本机，通过本地系统查看结果。
- MySQL 及其他基础服务运行在服务器上，由本机服务连接。
- 爬虫 API、数据库地址、账号和密钥均应可配置。
- 第一版风险提醒只在系统内显示，不发送邮件、飞书、微信或手机推送。

## 3. 功能需求

### FR-01 基金候选集合维护

系统应支持用户手动添加、修改和删除待分析基金。输入至少包括基金代码；系统需要尽可能解析基金名称、产品类型和份额类别，并处理无效代码或名称与代码不一致的情况。

候选集合是多基金筛选的输入范围。v1 不保证自动扫描全市场并发现候选基金；全市场自动选基是否纳入后续范围，另行决定。

### FR-02 多基金比较和筛选

系统应对用户输入的多只基金进行横向比较，并同时提供：

- 通用的客观评分和排序；
- 根据用户风险偏好和持有期限生成的个性化评分和排序；
- 每只基金的分级结果，例如重点关注、观察、中性或高风险；
- 综合分数、排名和可解释的分项结果；
- 排名理由、主要优势、主要风险和对应证据。

风险偏好默认“平衡”，持有期限默认“中长期（1 年以上）”，均可配置。v1 使用可解释的固定权重和四级标签“重点关注 / 观察 / 中性 / 高风险”；权重和阈值保存为配置，不写死在界面中，后续可调整。

### FR-03 当前持仓快照

系统应支持用户手动建立和更新当前持仓快照，并基于快照分析组合。v1 不实现逐笔买入、追加、赎回和定投流水。

持仓快照至少需要能表达：

- 基金代码和份额类别；
- 持有金额或持有份额；
- 成本或累计投入；
- 快照时间。

v1 至少要求基金代码/份额类别、持有金额或份额、累计投入和快照时间；当前估值优先由最新可用净值计算，无法获取时允许手动填写并标记来源。金额和份额至少填写一项。

组合分析至少应覆盖：

- 组合整体收益和亏损；
- 单只基金的仓位和对组合的贡献；
- 组合集中度及基金/行业/主题重复暴露；
- 组合回撤、波动和风险等级；
- 需要关注的单只基金或组合层风险原因。

### FR-04 持续跟踪和调度

系统应支持配置跟踪频率，默认在每个交易日收盘后执行完整分析。公告、新闻和舆情可以采用更短的抓取周期；当规则检测到明显异常时，可以提前触发一次额外风险复核。

需要跟踪的对象为用户明确加入跟踪范围的基金；v1 默认同时跟踪候选集合和当前持仓，使用同一全局频率配置。默认完整分析频率为每个交易日收盘后一次，公告/新闻/舆情默认每 4 小时抓取一次；频率可配置。

调度结果应能区分：

- 已成功更新的数据；
- 数据尚未更新或仍为估算值；
- 抓取失败、来源不可用或证据不足的情况。

### FR-05 风险检测和 Agent 复核

风险判断采用两阶段流程：

1. 固定规则根据净值、回撤、波动、规模、经理变更、持仓变化、公告和其他可量化信号发现异常并触发检查；
2. Agent 综合多来源证据，对异常进行解释、分级并生成需要关注的事项。

系统内的风险提醒至少应展示：

- 风险等级；
- 触发时间；
- 触发的规则或异常指标；
- Agent 的综合判断和不确定性说明；
- 相关基金、持仓或组合；
- 来源、抓取时间和原文链接；
- 建议用户进一步核查的事项。

Agent 不得在缺少数据或证据时伪装成确定结论。数据过期、来源冲突和抓取失败应明确显示。

### FR-06 数据来源和证据记录

每条用于排名、组合分析或风险提醒的重要事实，至少应保留来源标识、抓取时间、数据有效时间（如果来源提供）和原文链接或可追溯引用。

系统应区分：

- 基金正式公布的日终净值；
- 盘中估值或第三方估算；
- 新闻或公告中的已披露事实；
- Agent 的推断和判断；
- 社交媒体未经证实的线索。

不同来源之间发生冲突时，系统应保留冲突状态，而不是静默覆盖。

### FR-07 系统内结果展示

系统应让用户能够查看：

- 候选基金的排序、分级、分项指标和理由；
- 单只基金的详细分析及证据；
- 当前组合的收益、配置和风险；
- 持续跟踪产生的风险提醒及其历史记录；
- 数据更新时间和来源状态；
- 风险偏好、持有期限、跟踪频率和数据源配置。

第一版不要求外部消息推送。

## 4. 非功能需求

### NFR-01 可追溯性

用户看到的关键数字和结论应能够回溯到数据来源、抓取时间和分析时间。系统不能只保存一段无法解释来源的最终文字。

### NFR-02 数据新鲜度和状态透明

页面和提醒必须显示数据更新时间，并明确标记估算、过期、缺失和失败状态。数据不足时应降低结论置信度或阻止高等级判断。

### NFR-03 配置和可替换性

爬虫 API、数据源凭据、数据库连接、跟踪频率和用户偏好应通过配置管理。替换某一数据源不应要求重写筛选和风险判断规则。

### NFR-04 安全性

数据库凭据和外部 API 密钥不得写入代码库或分析报告。远程 MySQL 连接需要使用明确的访问控制和安全配置。

### NFR-05 可恢复性

单个来源抓取失败不应导致整个跟踪任务静默失败，也不应使用无来源的旧数据生成看似最新的高风险结论。失败状态需要可见并可重试。

### NFR-06 合规和访问约束

爬虫应遵守目标来源的访问条款、频率限制和 robots/接口要求；系统应避免把未经授权的登录态或受限内容作为默认依赖。

## 5. v1 明确不包含

- 逐笔交易流水、定投计划和自动对账；
- 从支付宝、券商、天天基金等账户自动导入持仓；
- 连接券商、自动下单或自动调仓；
- 邮件、飞书、微信、短信或手机推送；
- 将社交媒体传闻直接作为高可信事实；
- 在需求未确认前承诺全市场自动选基；
- 对未来净值或收益作保证性预测。

## 6. v1 验收标准

### AC-01 多基金筛选

给定一组手动输入的基金（包括不同份额类别），系统能够识别并展示每只基金，输出客观排序、个性化排序、分级标签、分数和带来源的理由。

### AC-02 个性化结果

修改风险偏好或持有期限后，系统能够重新计算个性化排序，并明确显示排序变化及影响因素；客观排序仍可单独查看。

### AC-03 组合快照

给定手动录入的当前持仓快照，系统能够计算组合层面的收益、仓位、集中度和风险摘要，并列出主要风险来源。

### AC-04 多来源跟踪

系统能够按配置的频率更新行情/净值、官方信息、新闻和舆情中的可用数据，并显示各来源的更新时间、状态和链接。

### AC-05 风险提醒

当固定规则发现异常时，系统能够生成一次 Agent 复核；提醒中同时包含风险等级、触发原因、综合解释和证据。没有足够证据时，系统应明确标注不确定或阻止高等级结论。

### AC-06 爬虫 API 配置

在不修改筛选、组合和风险判断业务规则的情况下，用户能够将默认简单爬虫切换为配置的外部爬虫 API，并看到来源状态。

### AC-07 本机服务和远程基础设施

服务可在本机运行，并能够按照配置连接远程 MySQL；连接信息和密钥不会出现在代码或前端可见内容中。

## 7. 最小实现默认值

以下内容采用最小实现默认值，后续可单独调整：

1. **基金类型**：优先支持股票型、混合型、指数型和 ETF 联接基金；其他类型允许录入但可能显示数据不足。
2. **持仓快照**：基金代码/份额类别、金额或份额、累计投入、快照时间为必填；估值默认由最新净值计算。
3. **偏好**：风险偏好默认平衡，持有期限默认中长期（1 年以上）。
4. **标签**：重点关注、观察、中性、高风险四级；阈值和权重配置化。
5. **评分**：客观排序与个性化排序均基于可获得的收益、回撤、波动、稳定性和风险信号；缺失指标不补造。
6. **跟踪对象**：候选集合和当前持仓均跟踪，共用一个可配置频率。
7. **首批来源**：先接入无需登录的公开行情/净值、基金公司或监管公告、公开财经新闻和可公开访问的舆情页面；外部爬虫 API 采用通用 HTTP 配置。
8. **提醒状态**：相同基金和同类原因在 24 小时内去重；风险升级立即生成新提醒；风险恢复后保留历史并标记恢复。
9. **本机界面**：默认浏览器访问的本机 Web 界面；具体视觉和交互在设计文档中另行确定。

## 8. 已确认决策记录

- D-001：第一版全部使用 Python。
- D-002：服务在本机运行，MySQL 等基础服务在服务器上。
- D-003：默认简单爬虫，并支持配置外部爬虫 API。
- D-004：第一版风险提醒只在系统内展示。
- D-005：第一版维护当前持仓快照，不实现交易流水。
- D-006：固定规则触发风险检查，Agent 负责多来源综合复核和解释。
- D-007：筛选结果同时提供分级标签、排序、分数和理由，并支持客观与个性化两种视图。
